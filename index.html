Payments and point-of-sale automation

At CORE Business Technologies I test the point-of-sale and payment software that CORE's clients use to take payments. The code is proprietary, so here is what I built and what it does, without the code.

A nightly regression suite of 800 tests

Selenium WebDriver, NUnit, C#/.NET, Bitbucket Pipelines

Two suites cover logins, transactions, voids, reversals, recalls, balancing and file creation. They run in CI every night and replaced about 20 hours of manual regression per run. A retry step reruns failures and produces a report, so I can tell configuration problems and third-party outages apart from real product defects.

Parallel Playwright suites for customer sites

Playwright, page objects, multi-customer configuration

Two customer-specific suites of 55 to 60 tests each. The product allows only one session per user, which normally rules out parallel runs. I gave each parallel worker its own test account, so four workers run side by side without logging each other out.

Responsive UI and accessibility testing

axe-core, keyboard and ARIA checks, WCAG 2.x

A 62-test suite checks the public payment site across screen sizes and scans each page for accessibility issues. I'm extending the same checks to the administrative portal, so the product's published accessibility claims are backed by automated evidence.

Performance, load and stress tests

Apache JMeter, Microsoft SQL Server

Nightly JMeter runs catch performance regressions before release. I also test SQL Server upgrade scripts against fresh installs, aged schemas, duplicate data and reruns.

Payment hardware in the field

Verifone MX915, PCI 6 and PCI 7 devices, VHQ, Ingenico, MagTek

I'm the Verifone subject-matter expert for about 2,000 devices across 20+ clients. I test chip, swipe and tap transactions, offline and failure scenarios and firmware updates, supported MX915 beta testing and PCI device rollouts, and travel to client sites to resolve production issues.

Security and payment-recovery scenarios

Authentication, sessions, access control

I designed tests for authentication, session handling, access control and duplicate-charge checks, ran them with AI-built tools, and tied each coverage gap to a remediation ticket.
